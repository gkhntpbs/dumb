# Boolean thinking API verification — 2026-10-16

The job API accepts optional boolean `think`. Omission preserves the backend default; explicit false and true retain their value through submission, durable storage, assignment and the Ollama request. Explicit null and nonboolean values fail with HTTP 400. Explicit modes require a worker advertising `think` at both admission and claim.

`output` contains only the final answer. `thinking` and `done_reason` remain separate caller-owned metadata. A thinking-only completion with `done_reason: length` remains a successful backend completion with empty final output. The combined decoded output, thinking, reason and error limit is 1048576 bytes. Escaped result envelopes and backend documents are bounded independently.

The regression files are `internal/queue/think_test.go`, `internal/server/think_test.go`, `internal/worker/think_test.go` and `internal/ollama/think_test.go`. They cover legacy fleet admission and claim, all three boolean modes through real HTTP clients and inert backends, durable optional false preservation, pre-feature gob and idempotency compatibility, pointer isolation, caller ownership, aggregate accounting and escaped-byte boundaries. Backend malformed, trailing and oversized JSON documents are rejected. The TypeScript tests cover wire omission, explicit false/true, metadata separation, invalid controls and actual Go-server integration.

These fixtures do not establish real-model behavior, production deployment, signed worker distribution or hosted CI acceptance. Deployment must preserve a consistent durable-queue snapshot. Restoring a predeployment snapshot discards newer jobs and requires an explicit recovery decision.
